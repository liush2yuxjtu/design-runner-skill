Provider names stay out of the plan.

Workflows request capabilities. Runner manifests map those capabilities to live tools. Missing support stays missing, instead of quietly sending work to another provider.

InspectRead document, screens, tokens, and components.
ResolveMatch required capabilities to the selected runner.
ExecuteEdit in bounded batches with explicit write policy.
CaptureCheck layout, pixels, clipping, and connectors.
VerifyExport the real target and leave local evidence.
runner catalog

Local first. Remote by permission.

The default runner writes local files and denies cloud access. Remote providers require explicit policy changes.

local-files

HTML, SVG, source, and Chromium QA. Safe default.

penpot-local

Self-hosted Penpot without a cloud requirement.

ardot-remote

GUI-free Ardot MCP after browser OAuth. Uses Ardot Cloud.

ardot-desktop

Desktop profile. Disabled until policy allows the app.

figma-remote

Remote Figma adapter with explicit cloud and write policy.

installation

Clone once. Pick a runner per project.

The repository root is the Skill. Extra folders contain the Pi extension, tests, documentation, and the Orbit example.

Safe local mode

git clone \
  https://github.com/liush2yuxjtu/design-runner-skill.git \
  ~/.agents/skills/design-runner

python3 ~/.agents/skills/design-runner/\
scripts/runner.py check

Ardot Remote in Pi

python3 runner.py use ardot-remote \
  --project . \
  --cloud allow \
  --desktop deny \
  --design-writes allow

/design-mcp connect ardot-remote

Fail closed means no surprise provider calls.

Unknown tools count as write-capable. Remote runners cannot start without cloud permission. Desktop profiles cannot start without desktop permission. Missing capabilities stop the workflow.
